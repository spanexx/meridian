What We Found

The transport seam is correct. Only app.config.ts decides mock versus HTTP, and flipping the useMock flag is the entire switch — no page touches a transport directly. HttpTransport already reads a backend base URL, attaches a Bearer token, and unwraps the same {success,data} envelope the mock returns.

But the page wiring is not. Only payouts.page.ts injects ApiClient. Every other page — dashboard, opportunities, executions, communities, profile, notifications, pool, and the auth flows — renders hardcoded wireframe fixtures from local consts. A backend flip would leave them frozen on fake data while only payouts went live (verified by grep: only payouts.page.ts + core/api + app.config reference ApiClient).

Five ApiClient methods have no backend contract. /executions, /executions/{id}, /payouts, /members/me/payouts, and /notifications are absent from docs/apis/, so they would 404 the moment the switch happened. The auth token provider is still a stub returning null.

Uncommitted spec expansion. api-client.spec.ts has 95 insertions of new test coverage (memberSettings, login2fa, opportunitiesMine, vettingQueue, executions, payoutsMine, communities, governance) that were not authored this session — a prior in-flight expansion. It needs a commit decision, not a silent drop.
